# AB5766 普通串口（UART1）极限测试

> 测试日期：2026-09-15 / 2026-09-18　固件分支：branch_01　结论：**初版最大无误码 3Mbps；原厂库重构版（分口阶梯测试）实测最大无误码 6Mbps，吞吐 421722 B/s**，8M 档受限于 RX 逐字节中断风暴（见 §6）

## 1. 测试原理

### 1.1 硬件连接

两块相同的 AB5766 开发板通过 3 根杜邦线对连，信号交叉、共地：

```
主板A(UART1 TX=PA0) ----> 主板B(UART1 RX=PA1)
主板A(UART1 RX=PA1) <---- 主板B(UART1 TX=PA0)
GND                ------- GND（必须共地）
```

- 电平 3.3V，PA0/PA1 通过 GPIO 交叉开关矩阵映射为 UART1 的 TX/RX（无固定复用限制）
- 调试打印独立走 UART0（PB3，单线，1.5Mbps），与被测串口物理隔离，互不干扰

### 1.2 主从角色与测试流程

两块板烧录同一份测试固件（`projects/microphone/test/`），开机进入独立的 `FUNC_UART_TEST` 功能态（不启动无线/音频，系统主频提升到 120M 排除干扰）：

- **角色**：适配器角色 = 主机（发起测试），话筒角色 = 从机（应答 + 统计），由 `wireless_role_is_adapter()` 自动区分
- **波特率爬坡**：主机按波特率表从低到高逐档测试，每档流程：
  1. 主机在当前波特率下发 `SET_BAUD` 命令，双方切换到目标波特率
  2. 主机发 `RUN` 命令，随后连续 **2 秒**发送数据块（257 字节/块 = 252 字节 payload + 5 字节帧头）
  3. 数据块带递增 seq 与 LRC 校验，从机逐块校验并统计：正确字节数 / 丢失块数（seq 断档）/ CRC 错块数
  4. 线路静默后主机发 `STATS_REQ`，从机回报统计，主机汇总打印一行结果
- **停止条件**：连续 2 档出现误码即停止爬坡；任一档满足「发送全部收到、miss=0、crc=0、drop=0」记为 PASS

### 1.3 帧协议

所有控制命令与数据块统一使用帧格式：

```
[A5][5A][cmd][len][payload(len)][lrc]    lrc = cmd ^ len ^ payload 全字节异或
```

- 理论吞吐基准：8N1 格式下每字节 10 bit，理论吞吐 = 波特率 / 10

### 1.4 测试环境

| 项目 | 配置 |
|---|---|
| 系统主频 | SYS_120M（测试态强制提升，串口波特率用独立晶振时钟不受影响） |
| UART1 时钟源 | XOSC24M 晶振（≤1.5M）；XOSC48M（>1.5M） |
| 收发方式 | TX 轮询逐字节发送；RX 中断逐字节收进 512B 环形缓冲 |

## 3. 测试结论

1. **普通串口 UART1 最大无误码波特率为 3Mbps**（8N1，实测吞吐 248472 B/s ≈ 242.6 Kbps 有效载荷速率的 82%）
2. 吞吐随波特率近似线性上升，效率从 97% 降至 82%——高波特率下逐字节 RX 中断开销占比增大（SYS_120M 下 3M 波特率仍可零误码接收）
3. XOSC24M 晶振源下 1.5M 实测稳定（与调试口经验一致）；2M 以上切换 XOSC48M 时钟源后依然零误码，说明 **XOSC48M 时钟源真实可用**
4. 数据块丢失/误码检测（seq + LRC 双重校验）在全部 8 档、累计约 230 万字节传输中未发现一处错误

## 4. 复测方法

1. `config_ab5766_le_mic.h` 中 `UART_SPEED_TEST_EN = 1`（`UART_LOOPBACK_TEST_EN = 0` 跳过单板回环）
2. `powershell -ExecutionPolicy Bypass -File projects/microphone/build.ps1` 编译
3. 两板烧录 `projects/microphone/Output/bin/download.xm`，接好 3 根线，复位即自动测试
4. 结果从调试打印口（PB3，1.5Mbps）查看，主机板输出完整爬坡表与 SUMMARY

## 5. 注意事项

- UART1 RX 中断必须在 `mic_bias_trim_init` 之后开启，否则 ADC trim 时序被干扰导致看门狗复位（详见 `docs/plan/AB5766_LE_Mic_PA0PA1_UART1收发接入与看门狗复位排错.md`）
- 测试固件将系统主频提升到 120M（`func_uart_test` 内 `sys_clk_set(SYS_120M)`）；高波特率下若维持 24M 主频，RX 逐字节中断将成为吞吐瓶颈
- 两块板必须共地；TX/RX 必须交叉（A.PA0→B.PA1、B.PA0→A.PA1），同脚直连无法通信

## 6. 12M 阶梯扩展测试（2026-09-18，原厂库重构版）

应用户要求把普通串口测到 12M。用原厂 driver 库重构了独立测试（`test/hsuart_vendor_test.c`，
`config_ab5766_le_mic.h` 中 `UART_TEST_PORT_SEL=0` 选普通串口；旧测试文件未动）。
方法差异：阶梯从已验证低档起步作锚点；**每档换挡 = 停 → 切时钟 → 重新 init**
（不再在活体外设上热切时钟——实测活体热切会引发中断派发异常 EPC=0，见高速串口文档 §9）；
时钟源 ≤1.5M 用 X24M、>1.5M 用 X48M（原厂 clk 库函数，X48M 档先开 CLK_GATE2_X48M 门控）。

| 波特率 | 主机发送 | 从机接收 | 结果 |
|---:|---:|---|---|
| 460800 | 86688 B | 全对 | PASS（锚点） |
| 921600 | 169596 B | 全对 | PASS（锚点） |
| 1500000 | 270144 B | 全对 | PASS（锚点） |
| 3000000 | 470484 B | 全对 | PASS |
| 4000000 | 666288 B | 全对 | PASS |
| 6000000 | 843444 B | 全对 | **PASS（最高无误码档）** |
| 8000000 | 1151136 B | 流中 WDT 复位 | FAIL |
| 12000000 | 无 BAUD_ACK（从机已重启） | — | 跳过 |

**结论：普通串口 UART1 最大无误码波特率 6Mbps，实测吞吐 421722 B/s**（8N1 理论值的 70%）。

- 锚点域（460800~3M，旧测试全 PASS 域）再次全 PASS，证明测试框架正确，高档数据可信
- 8M 档从机在数据流中看门狗复位：UART1 无 DMA，RX 逐字节中断在 8M（80 万中断/秒）下
  ISR 往返超过字节周期（833ns@12M/1.25µs@8M），RXPND 背靠背使主循环饿死喂不上看门狗——
  **这是 UART1 无 DMA 架构的物理上限，非软件缺陷**（低档锚点全对排除了其他因素）
- 效率说明：本版 TX 为逐字节阻塞发送（等待循环内含 WDT_CLR），6M 档效率 70%，低于旧版 3M 档的 82%——
  属发送路径保守换取鲁棒，接收侧 6M 内零丢字节
- 复测：`UART_HSUART_VENDOR_TEST_EN=1` + `UART_TEST_PORT_SEL=0`，两板烧同一固件，复位自动测试

### 6.1 X24M 全阶梯对照实验（2026-09-18）

与高速串口 X24M 对照实验（高速串口测试.md §9.1）对称，`VTEST_UART1_FORCE_X24M=1`
强制全阶梯不切时钟（全程 X24M），结果与 X48M 版完全等价：

| 波特率 | X24M 实测 | X48M 实测（§6 上表） |
|---:|---|---|
| 460800 ~ 1500000 | 全对（锚点域） | 全对 |
| 3000000 | 零误码 PASS | PASS |
| 4000000 | 零误码 PASS | PASS |
| 6000000 | **零误码 PASS（420210 B/s）** | **PASS（421722 B/s）** |
| 8000000 | 从机流中 WDT 复位（同 X48M 轮） | FAIL（同） |

**结论：时钟源 X24M/X48M 对 UART1 在其工作区间（≤6M）内无实质影响**——6M 在 X24M 的
4x 采样下同样零误码，进一步佐证"采样倍数不是决定因素"（与高速串口 §9.1 实验互相印证）；
**8M 失败与时钟源无关**（两轮以完全相同方式失败），坐实为 RX 逐字节中断风暴的 CPU 上限。
工程启示：UART1 阶梯可全程固定 X24M，省去时钟切换环节。
