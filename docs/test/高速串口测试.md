# AB5766 高速串口（HSUART）极限测试

> 测试日期：2026-09-15~18　固件分支：branch_01　结论：**原厂库（统一调库）版 1.5Mbps 零误码，实测吞吐 128772 B/s（§6）；12M 阶梯扩展：X48M 域 3M 达 99.4%、4M 达 99.6%，6M 起过采样裕量不足（§9）**

## 1. 测试原理

### 1.1 硬件连接与分时复用

HSUART 与普通串口测试使用**完全相同的 3 根线**（A.PA0↔B.PA1 交叉 + 共地）。AB5766 的 GPIO 交叉开关矩阵允许任意引脚映射为 HSUT0 的 TX/RX，因此 HSUART 分时复用 PA0/PA1：

1. 先在 UART1 上完成基础握手与普通串口测试
2. 主机静默 3.5 秒（从机空闲 3 秒自动回落到 115200 基础波特率实现再同步）
3. 主机发 `SWITCH_HS` 命令，双方各自关闭 UART1、初始化 HSUART（映射到同两根引脚，接线不变）
4. 进入 HSUART 波特率爬坡，流程与普通串口测试一致

### 1.2 收发方式（对齐原厂 bsp_huart.c 的 DMA 序列）

| 方向 | 方式 | 说明 |
|---|---|---|
| TX 数据块 | **DMA** 发送（`hsuart_dma_start(HSUT_TRANSMIT)`），等 TXPND 完成后发下一块 | 2 停止位（原厂配置） |
| TX 控制小帧 | 临时切 buf 模式逐字节发送，完成后恢复 DMA 模式 | 实测 DMA 模式下直接写 data 寄存器发不出去，见踩坑 3 与 §2.7 差异 4 |
| RX | **DMA** ping-pong 双缓冲（单块 128B）+ 空闲超时中断 | 原厂为单缓冲重挂同址，连续流下会丢字节，见踩坑 4 与 §2.7 差异 2 |
| RX 时钟 | XOSC24M 晶振（显式设置） | 原厂依赖复位默认源；本芯片默认源非晶振，见踩坑 2 与 §2.7 差异 1 |

理论吞吐基准：TX 为 8 数据位 + 1 起始位 + **2 停止位** = 每字节 11 bit，理论吞吐 = 波特率 / 11。

### 1.3 判定标准

与普通串口测试一致：2 秒发送窗口，从机回报「正确字节数 / seq 断档丢失块 / LRC 错块」，零误码（miss=0、crc=0、drop=0）才算 PASS；连续 2 档失败停止爬坡。

## 2. 原厂 HSUART 工作原理（原厂说明整理）

> 以下整理自原厂提供的 HSUART 原理说明（寄存器块结构 / 初始化 / 发送 / 接收 / buf 模式读取口 / 中断标志体系六部分），代码出处均已与本仓库逐一核对：`driver/driver_hsuart_reg.h`、`driver/driver_hsuart.c`、`driver/driver_clk.c`、`bsp/bsp_huart.c`。注意 `bsp_huart.c` 在当前工程配置下未参与编译（外层开关未打开），本测试的初始化/收发序列即照抄该文件的写法。本测试实现与原厂的差异见 §2.7。

### 2.1 寄存器块结构

`hsuart_typedef`（`driver_hsuart_reg.h:65~79`），共 13 个寄存器：

| 寄存器 | 作用 |
|---|---|
| `con` | 控制与状态：使能、中断使能、全部 PND 标志 |
| `cpnd` | 标志写 1 清零 |
| `baud` | 高 16 位 = RX 分频，低 16 位 = TX 分频（双份） |
| `data` | buf 模式发送数据口 |
| `tx_cnt` / `tx_adr` | 写入即启动发送 DMA（长度 / 地址） |
| `rx_cnt` / `rx_adr` | 写入即启动接收 DMA（长度 / 地址） |
| `fifo_cnt` | RX FIFO 当前字节数（DMA 已收多少） |
| `fifo` | buf 模式读取口：写 bit8 弹一字节，读 bit9 等就绪 |
| `fifo_adr` | FIFO 地址（本仓库未用） |
| `tmr_cnt` | RX 空闲超时计数（单位：位时间） |
| `flow_ctrl` | CTS/RTS 流控（本仓库未用） |

`con` 关键控制位：

| 位 | 名称 | 含义 |
|---|---|---|
| bit0/1 | URXEN / UTXEN | 收 / 发使能（`hsuart_cmd` 按 HSUT_RECEIVE / HSUT_TRANSMIT 分开操作） |
| bit2/3 | RXIE / TXIE | 收 / 发中断使能 |
| bit6 | RXLPBUFEN | RX 环形缓冲模式（HSUT_DMA_BUF_LOOP） |
| bit10 | HSUTTMREN | 空闲超时计数器使能 |
| bit11 | RXHF_PND | RX DMA 半满标志 |
| bit12/13 | RXPND / TXPND | 收 / 发完成标志 |
| bit14 | RXFAIL | 接收失败标志 |
| bit15 | TMROV | 空闲超时标志（判帧尾的核心信号） |
| bit16 | RXOVE_PND | RX 溢出标志 |
| bit17 | RXHF_IE | 半满中断使能 |
| bit18 | ONELINE | 单线模式 |

与普通串口的显著差异：**收/发使能分开（bit0/bit1）**，意味着可以只发不收或只收不发——`hsuart_cmd(HSUART_REG, HSUT_TRANSMIT, ENABLE)` 就是"纯发送用法"的写法（`bsp_huart.c:175` 的 else 分支）。

### 2.2 初始化：hsuart_init（driver_hsuart.c:19）

初始化六步：

1. `RSTCON0 |= 1<<2` —— 释放 HSUART 模块复位（每次 init 都做，保证外设从干净状态开始）
2. TX 配置：清旧值（停止位/字长/传输模式三段位）再写入 `tx_stop_bit | tx_word_len | tx_mode`
3. RX 配置：`rx_word_len | rx_mode`
4. 单线模式：清 `ONELINE` 后按 `one_line_en` 写入
5. 仅 RX-DMA 模式才处理缓冲模式位：清 `RXLPBUFEN` 后写入 `rx_dma_buf_mode`（SINGLE 或 LOOP）
6. 波特率：`clk_val = clk_hsut0_clk_get(CLK_VALUE_MODE_FREQ)`，`baud_reg = clk_val/baud - 1`，写入 `(baud_reg << 16) | baud_reg` —— **RX/TX 各占半字的双份分频，保持一致**

原理要点（原厂说明）：

- **时钟源是独立选路器，且原厂从不改选**：可选项共 5 类（枚举 7 个值，`driver_clk.h:117~127`）：XOSC24M / XOSC48M / UART0 CLKOUT / UART1 CLKOUT / PLL 分频档（DIV2/3/4）。与普通串口由代码显式 `clk_uart_clk_set()` 选定不同，原厂仓库没有一处调用 `clk_hsut0_clk_set`——HSUART 时钟源始终保持在复位默认值，原厂 1.5M/8M 两个在用场景即运行于该默认源上。若要改选时钟源须避开 PLL 分频档：`clk_hsut0_clk_get`（`driver_clk.c:106`）对 PLL 档返回 0，分频式 `(0/baud)-1` 会算出错误波特率（实测代码更严格：`CLKCON0` 第 19 位置位时对所有档一律返回 0）
- **baud = 0 保护**：`hsuart_init` 遇 0 直接返回不分频（`driver_hsuart.c:52~54`）——调用者可分两步初始化（先配置后给波特率）
- **TX 固定 2 停止位**：BSP 层初始化选 `HSUT_STOP_BIT_2BIT`（`bsp_huart.c:155`）——多 1 位停止位给单线半双工的方向切换留裕量，对端按 8N2 或宽容解析即可

### 2.3 发送：hsuart_dma_start 的"寄存器即 DMA"（driver_hsuart.c:316）

```c
void hsuart_dma_start(hsuart_typedef *huartx, HSUT_REC_TRA_CMD sel, uint32_t addr, uint16_t len)
{
    if (sel == HSUT_RECEIVE) {           // 写入即启动接收
        huartx->rx_adr = addr;
        huartx->rx_cnt = (uint32_t)len;
    } else if (sel == HSUT_TRANSMIT) {   // 写入即启动发送
        huartx->tx_adr = addr;
        huartx->tx_cnt = (uint32_t)len;
    }
}
```

**"写寄存器 = 启动 DMA"是这个外设最核心的设计**：没有独立的"DMA 启动命令寄存器"，向 `tx_adr`/`tx_cnt` 写值的动作本身就是触发；对应地 `hsuart_dma_stop`（`driver_hsuart.c:334`）把 cnt 写 0 即停止。

BSP 层发送封装 `bsp_huart_tx`（`bsp_huart.c:97~102`）：等上一次发完（轮询 TXPND）→ `hsuart_dma_start` 启动、立即返回。

应用铁律（TX 侧无任何中间缓冲，buf 就是 DMA 源）：

1. **buf 在 TXPND 置位前不得修改/释放**：DMA 从原地址逐字节读出，改 buf 等于改还没上线的线上数据
2. **发送不能排队**：寄存器只有一组 `tx_adr/tx_cnt`，下一次 `bsp_huart_tx` 开头的 while 会等上一次 TXPND，多次发送天然串行化
3. **需要立即复用 buf 时先调 `bsp_huart_wait_txdone()`**（`bsp_huart.c:90~94`）阻塞轮询

buf 模式备用发送路径：`hsuart_send_data()`（`driver_hsuart.c:94`）逐字节写 `data` 寄存器，配合 `huart_putchar()`，用于 DMA 不可达地址（≥0x10000000 片外区）回退或零星字节。

### 2.4 接收：DMA + 空闲超时判帧（核心机制）

接收的硬件配合件是三个：**RX DMA**（字节自动落 rxbuf）、**fifo_cnt**（实时计数）、**空闲计时器**（tmr_cnt，线上静默超阈值置 TMROV）。

BSP 层 ISR `huart_rx_isr`（`bsp_huart.c:77~88`）触发条件二选一：`HSUART_IT_RX`（缓冲收满）或 `HSUART_IT_RX_TMR_OV`（空闲超时）。命中后三个动作的顺序是承重的：

1. **回调**（指针 + `hsuart_get_fifo_counter()` 实际长度）把数据交出去
2. **清标志**
3. **重启 RX DMA 指向同一块 rxbuf**

回调返回后 DMA 立刻重新武装，因此回调有两条铁律：

1. 必须当场拷贝/消费数据——下一帧会覆盖 rxbuf
2. 只能做轻量工作（memcpy + 入队 + 发消息），重活转主循环

帧尾判定的阈值由 `hsuart_rx_idle_config(HSUART_REG, HSUART_OV_CNT, ENABLE)` 设置，`HSUART_OV_CNT = 0x20`（32 位时间，`bsp_huart.h:4`）：9600bps 下约 3.3ms，1.5Mbps 下约 21μs。设置原则：**大于帧内字节间最大合法间隔，小于调用方两帧之间的最小间隔**。

### 2.5 buf 模式读取口：hsuart_receive_data_from_fifo（driver_hsuart.c:120）

ISR 重启 DMA 的空窗与帧截断场景下，残余字节留在硬件 FIFO，从 `fifo` 寄存器弹出：写 bit8 触发弹出、轮询 bit9 等就绪、读低 8 位取数——`fifo` 寄存器用同一地址的不同位实现"命令/状态/数据"三合一。配套读 `fifo_cnt`（先查再取）；请求数不得超过 FIFO 实有，否则返回 FAILED。

### 2.6 中断注册与标志体系

`hsuart_pic_config`（`driver_hsuart.c:185`）与普通串口同构，中断源四个：

| 标志 | 置位条件 | 原厂仓库用法 |
|---|---|---|
| HSUART_IT_RX | RX DMA 缓冲收满 | 帧结束判定之一 |
| HSUART_IT_RX_TMR_OV | 线上静默超 tmr_cnt | 变长帧尾判定（核心） |
| HSUART_IT_TX | 一笔 DMA 发送完成 | TX 轮询等待 |
| HSUART_IT_RX_DMA_HF | RX DMA 收到一半 | 未使用（LOOP 模式专用） |

清标志一律走 `cpnd` 写 1 清零；ISR 及收发热点函数带 `AT(.com_text.huart.*)` 段属性放 RAM，保证任何时钟/缓存状态下可执行。

### 2.7 本测试实现与原厂的差异对照

先说一致的部分——测试代码完全照抄原厂 `bsp_huart.c` 的序列：初始化参数（TX/RX 均 DMA 模式、TX 2 停止位、8bit 字长、双线、RX SINGLE 缓冲模式、空闲阈值 0x20、中断优先级 0、波特率交驱动按当前时钟源自动计算）；ISR 触发条件（收满 或 空闲超时）；标志清零方式；`fifo_cnt` 在重挂 DMA 前先读；TX 块发送"等上次 TXPND → 启动 → 等完成"与原厂 `bsp_huart_tx` + `bsp_huart_wait_txdone` 组合等价。

差异共 6 处，均在 `projects/microphone/test/uart_test_hw.c` 内有对应注释：

| # | 环节 | 原厂做法 | 本测试实现 | 差异原因 |
|---|---|---|---|---|
| 1 | 时钟源 | 从不调用 `clk_hsut0_clk_set`，依赖复位默认源 | init 前**显式** `clk_hsut0_clk_set(CLK_HSUT0_XOSC24M)`（全仓库唯一调用点，`uart_test_hw.c:228`） | 原厂"默认源可用"的前提在本芯片双板实测不成立：默认源非晶振（疑似 RC），单板回环同源 PASS、双板独立时钟下每块数据全 LRC 错（踩坑 2）。仍选非 PLL 档，驱动自动算分频保持有效 |
| 2 | RX 缓冲与 ISR 顺序 | SINGLE 单缓冲；ISR **先回调 → 再清标志 → 最后重挂同一块** rxbuf | **ping-pong 双缓冲**；ISR **先重挂另一块 → 再清标志 → 最后搬运**刚收满的块 | 连续 2 秒不间断数据流下，单缓冲"写满→重挂"间隙丢字节（每块必丢、LRC 全错，踩坑 4）；先重挂把硬件盲区压到微秒级。原厂场景是变长命令帧（帧间有空闲），不触发该问题 |
| 3 | RX 溢出处理 | BSP ISR 不处理 `RXOVE_PND` | ISR 里查 `con` 的 `HSUT0CON_RXOVE_PND`：计数进 drop 统计，并按"cpnd 写 1 清零"原则写 `HSUT0CPND_CRXOVEPND` 清掉 | 吞吐测试需要区分丢字节发生在硬件层（重挂间隙）还是软件层（环形缓冲满），drop/crc 分开统计（踩坑 4 的量化手段） |
| 4 | 控制小帧发送 | TX 固定 DMA 模式从不运行时切模式；`hsuart_send_data` 的 buf 路径仅用于 buf 模式 / 片外地址回退 | TX 保持 DMA 模式，发小帧时**临时清 `HSUT0CON_TXTRSMODE` 切 buf 模式**，发完等 TXPND 再恢复 DMA 位 | 控制帧（握手/统计应答）必须与数据流共线分时；实测 DMA 模式下直接写 `data` 寄存器发不出去（踩坑 3），临时切模式是借用原厂 buf 路径的最小改动 |
| 5 | TX 阻塞语义 | `bsp_huart_tx` 启动即返回，需要等再调 `bsp_huart_wait_txdone` | `uart_hw_hsuart_tx_block` 把"等上次完成 → 启动 → 等完成"封装为阻塞调用 | 吞吐测试连续满速发送且 buf 发完即复用，正是原厂铁律 1/3 要求的场景；机制同原厂，仅封装形式不同 |
| 6 | RX 缓冲模式档位 | 驱动支持 SINGLE/LOOP 两种 `rx_dma_buf_mode`；BSP 用 SINGLE，LOOP 专属的半满中断 `RX_DMA_HF` 未用 | SINGLE + 软件 ping-pong，未启用硬件 LOOP（`RXLPBUFEN`） | 尽量贴原厂验证过的序列，硬件 LOOP 模式在 AB5766 上无先例；若后续冲 >1.5M 档，LOOP + 半满中断是候选优化（见测试结论） |

另有一处与原厂说明的**实测出入**需要单独强调：原厂说明称"复位默认时钟源可用（原厂在用场景即运行于该默认源）"，但 AB5766 双板实测中默认源无法保证两板独立时钟下的波特率一致（差异 1）。这不否定原厂原理——单板同源场景默认源确实可用——但说明 AB5766 的 HSUT0 复位默认源与原厂文档撰写时所依据的芯片状态不同，**在 AB5766 上使用 HSUART 必须显式选晶振源**。

双板对连实测（HSUART 阶段，每档 2 秒窗口）：

| 波特率 | 实际发送 | 实测吞吐 | 达 baud/10 | 达 baud/11 理论 | 从机接收校验 | 结果 |
|---:|---:|---:|---:|---:|---|---|
| 460800 | 81648 B / 2002ms | 40783 B/s | 88% | 97% | good=81648 miss=0 crc=0 | PASS |
| 921600 | 161784 B / 2001ms | 80851 B/s | 87% | 97% | good=161784 miss=0 crc=0 | PASS |
| 1500000 | 260064 B / 2001ms | 129967 B/s | 86% | 95% | good=259560 miss=2 crc=1 | FAIL |

1.5M 档细节：1030 块中 1029 块正确，丢失 2 块（约 504 字节）+ 1 块 LRC 错，**正确率 99.8%**，未达零误码标准。

## 4. 测试结论

1. **高速串口 HSUART 最大无误码波特率为 921600**（实测吞吐 80851 B/s，达到 2 停止位理论值的 97%）
2. 1.5Mbps 实测 99.8% 无误码（偶发丢失 2 个 DMA 缓冲周期的数据），若放宽为非零误码标准则基本可用；进一步提升可尝试 RX DMA 循环缓冲（LOOP）模式或提高 HSUART 中断优先级
3. HSUART 双向链路效率与普通串口相当（扣除 2 停止位开销后达 97% vs UART1 的 94%），**DMA 收发通道本身不是瓶颈**
4. 按字节效率折算：921600bps 的 HSUART（80851 B/s）低于 3Mbps 的 UART1（248472 B/s）——本芯片上「高速串口」的优势在于 DMA 收发释放 CPU，而非绝对波特率更高；受原厂验证域与时钟源限制，本次未探索 >1.5M 档位

## 5. 踩坑记录（重要，HSUART 在 AB5766 上属首次验证）

以下问题均通过双板日志与逐轮试验定位，修复方式已固化在 `projects/microphone/test/uart_test_hw.c`：

1. **中断序列必须用原厂 bsp_huart.c 的完整 DMA 初始化**
   自写初始化（无论 DMA 还是 buf 模式）在使能 HSUART 中断后立即 `EXCEPT`（中断异常 + IRQ15 pending）/ `REQ TOUT` 并看门狗复位。`libplatform.a` 中无任何 HSUART 符号——本 SDK 官方从未用过 HSUART，`driver_hsuart.c` 系从 AB202X 移植，`hsuart_init` 中 `RSTCON0 |= 1<<2` 等操作在 AB5766 上的副作用未知。
2. **时钟源必须显式选 XOSC24M 晶振**
   原厂代码从不设置 HSUT0 时钟 mux（依赖复位默认值）。实测：单板回环（收发同源）全 PASS，双板（两板独立时钟）收到的每个数据块全部 LRC 错——默认时钟源非晶振（疑似 RC），两板独立偏差导致采样错位。显式 `clk_hsut0_clk_set(CLK_HSUT0_XOSC24M)` 后解决。
3. **控制小帧发送必须临时切 buf 模式**
   TX 配置为 DMA 模式时直接写 data 寄存器发送小帧（原厂 `huart_putchar` 的写法）未经 AB5766 验证，实测从机应答发不出去（主机 `no response`）。改为发送前后切换 `HSUT0CON_TXTRSMODE` 位（buf 模式发单字节 → 等完成 → 恢复 DMA 模式）。
4. **RX DMA 单缓冲在连续流下丢字节**
   单缓冲写满触发中断到重新挂 DMA 之间存在间隙，连续数据流下每个 DMA 周期丢失字节（表现为每个数据块 LRC 全错、错误数 ≈ 块数；单板回环因发送有停顿而不复现）。改为 ping-pong 双缓冲：中断里先把 DMA 切到另一块缓冲（微秒级），再从容搬运刚收满的块。
5. **从机空闲回落逻辑不得作用于 HSUART**
   断链恢复用的「空闲 3 秒回落 115200」若在 HSUART 模式生效，会改掉正在测试的波特率导致后续全部 no response。已限定仅在 UART1 模式生效。

### 6.1 实验过程与三条边界结论（全部双板实证）

| # | 原厂做法 | 实测结果 | 结论 |
|---|---|---|---|
| 1 | 时钟源不动（复位默认，寄存器读回 idx=0/24M） | hello@115200 通，数据块两档全 LRC 错（good=0） | 默认源双板精度不可用，**必须** `clk_hsut0_clk_set(CLK_HSUT0_XOSC24M)` |

1. `config_ab5766_le_mic.h` 中 `UART_SPEED_TEST_EN = 1`；若需先做单板回环自检，再置 `UART_LOOPBACK_TEST_EN = 1`（跳线 PA0-PA1，两板 UART1@115200~3M 与 HSUART@460800/921600/1.5M 回环全部 PASS）
2. 编译、双板烧录、交叉接线同普通串口测试
3. 测试全程约 1 分钟自动完成：hello 握手 → UART1 爬坡 → 自动切换 HSUART → HSUART 爬坡 → SUMMARY

## 8. 注意事项

- HSUART 时钟源若要探索 >1.5M 档位（XOSC48M / PLL 分频），需注意 `clk_hsut0_clk_get()` 对 PLL 档返回 0，`hsuart_baud_config()` 会算错分频，必须手工写 `HSUART_REG->baud = (div<<16)|div`；PLL 档位频率需以 `pll_clk_nhz_get()` 实测为准
- 主机板测试中曾出现一次 `LVD_RST`（低压复位），多板多 USB 设备同口供电时注意供电余量
- 从机 HSUART 收发统计中的 `drop` 字段为 RX 环形缓冲溢出计数，`crc` 为 LRC 校验失败帧数，可用于快速定位丢字节发生在硬件层（drop）还是内容层（crc）

## 9. 12M 阶梯扩展测试（2026-09-18，分口测试）

应用户要求把高速串口测到 12M。采用分口测试结构（`UART_TEST_PORT_SEL=1` 选高速串口，
一个固件只测一个端口），阶梯从已验证低档起步作锚点，换档策略：
**同时钟源内用原厂 `huart_set_baudrate` 活体切换（§6 零误码 PASS 版同款），
跨时钟源（1.5M→3M，X24M→X48M）才"停→切时钟→重新 init"**。
时钟源 ≤1.5M=X24M（已验证零误码域）、>1.5M=X48M（X48M 档先开 CLK_GATE2_X48M 门控）。

| 波特率 | 时钟源 | 主机发送 | 从机接收 | 结果 |
|---:|---|---:|---|---|
| 460800 | X24M | 81396 B | 全对 | **PASS 零误码**（锚点） |
| 921600 | X24M | 160776 B | 全对 | **PASS 零误码**（锚点） |
| 1500000 | X24M | 257544 B | 全对 | **PASS 零误码**（锚点） |
| 3000000 | X48M | 507528 B | 99.4%（miss=12 crc=6） | FAIL |
| 4000000 | X48M | 665280 B | 99.6%（miss=10 crc=5） | FAIL |
| 6000000 | X48M | 965916 B | 60.3%（miss=1517 crc=760） | FAIL |
| 8000000 | X48M | 1247148 B | 0.4% | FAIL |
| 12000000 | X48M | 1760220 B | 0.2% | FAIL |

**结论：HSUART 最大无误码波特率保持 1.5Mbps（128772 B/s）**；X48M 新域 3M/4M 能通但非零误码，
6M 起明显劣化、8M 以上基本不通——失败率与**绝对波特率**强相关（成因分析见 §9.1 对照实验）。

过程记录（对后续使用 HSUART 的建议）：

1. **不要在活体外设上热切时钟**：初版在 init 前对已使能的 UART1 热切时钟，第一条 RX 中断即
   `EXCEPT EPC=0`（空指针派发）；改回"停→切→重新 init"后消失。经原厂派发代码确认
   （`cpu_irq_comm` 对空表项有 `beqz` 保护、`sys_irq_init` pr=0 重注册安全），
   EPC=0 定位为派发/注册窗口的竞态，规避方法即上述换档策略
2. **同源活体换档必须复位每档统计**（good/seq/drop），否则跨档累计产生假 miss/假 FAIL
3. 双板开机多次 `LVD_RST`（低压复位），12M 阶梯高吞吐下供电余量务必充足
4. 复测：`UART_HSUART_VENDOR_TEST_EN=1` + `UART_TEST_PORT_SEL=1`，两板烧同一固件，复位自动测试

### 9.1 X24M 对照实验（推翻过采样模型，2026-09-18）

初版分析曾把 X48M 域的失败归因于"过采样倍数不足"（每位的时钟采样次数 = 时钟÷波特率，
X48M 下 3M=16x、12M=4x）。为此做了强制 X24M 的对照实验（`VTEST_HS_FORCE_X24M=1`，
全阶梯不切时钟），结果**推翻了该模型**：

| 波特率 | 过采样(X24M/X48M) | X24M 实测 | X48M 实测 |
|---:|---:|---|---|
| 460800 | 52x/104x | PASS 零误码 | PASS 零误码 |
| 921600 | 26x/52x | PASS 零误码 | PASS 零误码 |
| 1500000 | 16x/32x | 99.999%（差 2 块） | PASS 零误码 |
| 3000000 | 8x/16x | **PASS 零误码** | 99.4% |
| 4000000 | 6x/12x | 99.6% | 99.6% |
| 6000000 | 4x/8x | 70.9% | 60.3% |
| 8000000 | 3x/6x | 0.3% | 0.4% |
| 12000000 | 2x/4x | 无 STATS（链路断） | 0.2% |

反例：同为 8x 过采样，X24M@3M 零误码而 X48M@6M 仅 60%；同为 6x，X24M@4M 99.6% 而
X48M@8M 0.3%。**过采样倍数不是决定因素，绝对波特率才是**：HSUART 在 AB5766 上
≤4M 两种时钟源表现一致（4M≈99.6%），≥6M 明确劣化、≥8M 基本不通——判定为
HSUART 外设在本芯片上 ~5M 以上的硬限制（外设 IP 与板级信号质量的归属待示波器区分）。

实验说明：
- X24M 各档分频恰为整数（3M=div7、4M=div5、6M=div3、8M=div2、12M=div1），无量化误差；
  460800/921600 有 +0.16% 分频截断（锚点域已实测无影响）
- 全程同源活体换档（`huart_set_baudrate`），不经过任何重新 init 窗口，本轮无 EPC=0
- 1.5M/3M 档"零误码 vs 99.x%"的差异在供电噪声范围内（双板每次开机 LVD_RST），
  精细分档需先解决供电后多轮复测

## 10. FAQ：为什么高速串口实测上限反而低于普通串口？它的意义是什么？

### 10.1 为什么 HSUART 实测上限（1.5M 零误码/4M 可用）低于 UART1（6M 零误码）

1. **UART1 是成熟外设，HSUART 在本芯片上是"原厂从未用过"的 IP**。`libplatform.a` 中没有任何
   HSUART 符号——原厂在 AB5766 上从未启用它，驱动系从 AB202X 移植。其 IP 在本芯片上的实际
   表征此前无人做过，本次测试等于首次摸底：**~5M 是它在本芯片的硬限制**（X24M/X48M 两源
   表现一致，证明与时钟源/过采样无关，属 IP 或引脚信号质量的固有边界，详见 §9.1）
2. **UART1 的 6M 是"空载极限"**：无 DMA，6M = 每秒 60 万次 RX 逐字节中断，本测试 CPU 空载
   才扛住。真实系统跑着无线协议栈与音频中断，高档位逐字节中断被抢占即丢字节——UART1 的
   高波特率在实战中到不了 6M
3. 实测失败曲线与波特率（而非采样倍数）强相关：≤4M 两种时钟源表现一致（4M≈99.6%），
   ≥6M 劣化、≥8M 基本不通——时钟源无法绕过该边界（PLL 档大概率同样无效，且 `clk_hsut0_clk_get`
   对 PLL 档返回 0 需手工分频，性价比低）

### 10.2 HSUART 的意义：DMA 释放 CPU，而非波特率竞赛

| | UART1（6M，逐字节 RX 中断） | HSUART（1.5M，全 DMA） |
|---|---|---|
| CPU 占用 | 每秒 60 万次中断，几乎吃满 CPU | 每 128 字节才一次中断，占用趋近于零 |
| 真实系统中 | 高档位不可用（被其他中断抢占即丢字节） | 确定性高，可与无线/音频并存 |
| 吞吐 | 421722 B/s（实验室极限，代价是整个 CPU） | 128772 B/s（可持续，CPU 近乎空闲） |

一句话：**UART1 的高波特率是拿整个 CPU 换来的实验室数字；HSUART 1.5M 是系统里真正能用的
通道**。无线麦的实际数据率（音频+控制）远低于 1.5M，HSUART 在不干扰主业的前提下稳定承载，
这正是它的定位——原厂文档对其的描述也是"DMA 收发释放 CPU"，另支持 LOOP 环形缓冲、
单线半双工等模式。

本次测试的附加成果：**"AB5766 HSUART ≤1.5M 零误码、4M 可用、≥6M 不可用"这一边界此前
无人知晓**（原厂未用、无文档），现已实测清楚并记录于本文档，后续使用者可完全避坑。
