## 1. 充电仓功能模型（源自码与 PDF 归纳）

充电仓（charging case）通过 VUSB 给仓内无线麦供电。SDK 对充电仓的支持由两层开关决定：

| 开关 | 位置 | 含义 |
| --- | --- | --- |
| `BSP_CHARGE_BOX_EN` | 编译期（`projects/microphone/config_ab5766_le_mic.h:35`，当前 = **0**） | 充电仓功能编译总开关 |
| `sys_cb.charge_box_type` | 运行时（`bsp_sys.c:130`，取自 `xcfg_cb.ch_box_type`） | 0=不支持充电仓；1=常 5V 类型；2=维持电压类型 |
| `xcfg_cb.charge_en` | `.setting` | 充电功能运行时开关 |
| `xcfg_cb.charge_working_while_charging` | `.setting` | True=边充边工作；False=阻塞充电（不开机模式） |

**关键硬件检测位**（`bsp/bsp_charge.h`）：

- `CHARGE_DC_IN()` = `RTCCON bit20`（`>>19 & 0x02`）：VUSB 5V 是否插入。
- `CHARGE_INBOX()` = `RTCCON bit22`（`>>22 & 0x01`）：是否在仓内（仓通过维持电压/inbox 信号区分"插 5V 直充"与"在仓内"）。

**充电状态机**（`driver_charge.h`，`charge_ctl.chag_sta`）：

```
CHARGE_STA_UNINIT(0) → CHARGE_STA_OFF(1) → CHARGE_STA_OFF_BUT_DC_IN(2，充满/停止但仍连DC)
  → CHARGE_STA_ON_TRICKLE(3 涓流) → CHARGE_STA_ON_CON_CURR(4 恒流) → CHARGE_STA_ON_CON_VOL(5 恒压) → 2(充满)
```

**充电仓三类典型场景**（PDF 5.4.3）：

1. **5V 唤醒（入仓充电）**：入仓 → VUSB 上 5V → 唤醒开机/阻塞充电 → 充满关机。
2. **0V 唤醒 / INBOX 唤醒（出仓）**：出仓 → VUSB 掉到维持电压以下 → INBOX 下降沿唤醒开机。
3. **维持电压类型仓（`ch_box_type=2`）**：仓低电时 VUSB 不升到 5V，`func.c:59-66` 改用 `CHARGE_INBOX()` 检测入仓关机。

> ⚠️ PDF 5.4.3 关键约束：**关机过程中若有唤醒源 pending，系统会立即 reset、关机失败**。配置 vusb 唤醒需等 5V 掉下去后再关机；配置 inbox 下降沿唤醒时 VUSB 端需有维持电压。测试必须覆盖这两条边界。

## 2. 测试环境与前置条件

### 2.1 硬件

| 设备 | 数量 | 说明 |
| --- | --- | --- |
| AB5766 无线麦开发板（发射端） | 1 | 锂电池（满充一次作为基准） |
| AB5766 无线麦开发板（接收端，可选） | 1 | 充电代码公共，主要测发射端 |
| 充电仓（或模拟工装） | 1 | 需能提供：5V 常供、维持电压（2.6V 以下）、inbox 信号；无实际仓时用可调电源 + 开关模拟 |
| 可调直流电源 | 1 | 0~5.5V，模拟 VUSB，带电流读数（mA 级） |
| 万用表 | 1 | 测 VBAT / VUSB 电压 |
| USB 串口（CH340 等）+ PC | 1 | 抓日志，串口波特率按工程配置（默认工程 UART 打印） |
| 烧录器（Downloader） | 1 | 烧录固件与 `.setting` |

### 2.2 软件配置

1. 固件编译配置 `BSP_CHARGE_EN = 1`；测试充电仓完整功能需改为 `BSP_CHARGE_BOX_EN = 1` 重新编译（当前仓库为 0，见 `config_ab5766_le_mic.h:35`）。
2. `.setting` 中确认/设置：`charge_en=True`、`ch_box_type`（1 或 2，按仓类型）、`charge_working_while_charging`（两种模式各测一轮）。
3. 串口日志过滤关键字：`charge: `、`[charge]`、`-->charge full`、`charge exit`。

### 2.3 判定基准

- 充电参数基准（PDF 5.4.1/5.4.3 + `bsp_charge.c`）：涓流截止电压 2.9V/3.0V，截止电压默认 4.35V（`CHARGE_CUTOFF_VOL_4V35`），恒流/涓流电流、截止电流由 `.setting`（`charge_constant_curr` / `charge_trickle_curr` / `charge_stop_curr`）配置。
- 电量检测：10bit SARADC，参考 VBG，主循环 1s 测一次，带滤波。

## 4. 测试项详细步骤

### T1 5V 插入检测（DC IN）

**前置**：`charge_en=True`，`BSP_CHARGE_BOX_EN` 可为 0（本项不依赖仓）。
**步骤**：
1. 开机进入正常工作状态，串口连接。
2. 用可调电源从 0V 缓升至 5V 接 VUSB，观察电流突变与日志。
3. 再降至电池电压+0.1V（约低于 4.2V），观察是否判为未插入。
**预期**：VUSB ≥ 电池电压+0.2V（一般 5V）时判为插入；日志出现 `charge: 3/4/5`（进入充电状态）。低于阈值不误判。
**记录**：判定阈值实测值。

### T2 INBOX 在仓检测

**前置**：`BSP_CHARGE_BOX_EN=1`、`ch_box_type=1/2`。
**步骤**：
1. 模拟仓给出维持电压/inbox 信号（`CHARGE_INBOX()`=1）。
2. 在串口或调试器观察 `RTCCON bit22`；或临时加打印验证。
3. 拔出仓观察 bit22 变化与响应时间（`bsp_charge.c:85-92` 有最多 500ms 的出仓确认窗口）。
**预期**：入仓置位、出仓清除，响应 ≤500ms。

### T3 三段充电状态机

**前置**：电池放电至 <2.9V（触发涓流），可调电源 5V。
**步骤**：
1. 入仓充电，抓全日志 `charge: 3 → 4 → 5`。
2. 万用表监测 VBAT：记录涓流段结束电压（2.9V/3.0V）、恒流段电流（对照 `.setting` 的 `charge_constant_curr`）、恒压段电压（4.35V 附近）。
3. 记录每段时长。
**预期**：状态迁移顺序正确；恒流段电流 = 配置值 ±10%；恒压段电压稳定在截止电压。

### T4 充满判定与停充

**前置**：T3 进行中。
**步骤**：
1. 充电进入恒压段后持续监测电流，直到截止电流满足（`CHARGE_IS_IPEND()`）。
2. 观察日志 `charge: 2`（OFF_BUT_DC_IN）与充电电流归零。
3. 验证截止计时：人为让电压先达标、电流迟迟不降（小电池难模拟，可改小 `charge_stop_curr` 或用 `charge_set_stop_time()` 缩短观察），验证超时停充。
**预期**：按"先 V 判据后 I 判据"流程充满停充；截止计时兜底生效。

### T5 充满后关机

**前置**：`CHARGE_FULL_PWROFF_EN=1`（`bsp_charge.c:10`）。
**步骤**：
1. 阻塞充电模式充满 → 观察 `-->charge full, enter pwroff`（`bsp_charge.c:139`）→ 设备进入关机流程。
2. 边充边工作模式充满 → 状态到 OFF_BUT_DC_IN 后 `func_cb.sta=FUNC_PWROFF`。
3. 充满关机后保持在仓，确认不再重启（`bsp_charge_init` 中充满退出循环逻辑）。
**预期**：充满自动关机且停在关机态，不循环开关机。

### T6 复充

**前置**：`RECHARGE_EN=1`（需打开 `bsp_charge.c:9` 重编译），充满状态。
**步骤**：
1. 充满后用电子负载/电阻使 VBAT 缓降到 <4.2V（`RECHARGE_THRESHOLD`）。
2. 观察日志 `[charge] start re-charging`，状态回到 4（恒流）。
**预期**：回落到阈值以下自动复充，阈值以上不复充（防抖）。

### T7 边充边工作模式

**前置**：`charge_working_while_charging=True`（发射端 `.setting` 当前即 True）。
**步骤**：
1. 开机工作（发射音频/无线连接正常），插入 5V 入仓。
2. 确认主循环持续调用 `bsp_charge_process()`（`func.c:52`），功能不中断。
3. 全程监测无线连接稳定性、音频无异常，充电电流正常。
**预期**：充电与工作并行，音频/连接无劣化；充电状态日志正常推进。

### T8 充电不开机（阻塞充电）模式

**前置**：`charge_working_while_charging=False`。
**步骤**：
1. 关机状态插入 5V → 设备不进主功能，进入 `bsp_charge_init` 充电循环（`bsp_charge.c:64-75`）。
2. 工作状态插入 5V → 观察进入阻塞充电（中断工作）。
3. 充满或拔出后观察后续行为（关机/开机按配置）。
**预期**：阻塞期间仅充电不工作；充满走 T5；拔出恢复。

### T9 5V 唤醒开机（入仓充电）

**前置**：关机态；唤醒源含 `WK_LP_VUSB`；`poweron_vusb_out_en` 按需。
**步骤**：
1. 关机后插入 5V（模拟入仓），观察自动开机。
2. 观察 `power_on_check()`（`bsp_sys.c:150`）逻辑：按 `poweron_first_bat_en`/`poweron_vusb_out_en` 决定是否直接开机。
**预期**：入仓 5V 唤醒 → 按配置开机进入充电/工作。

### T10 0V / INBOX 出仓唤醒开机

**前置**：仓内关机态；唤醒源含 `WK_LP_INBOX`（`func_lowpwr.c:374-379`）。
**步骤**：
1. 设备在仓内关机，维持电压存在。
2. 出仓（维持电压撤除，inbox 下降沿）→ 观察唤醒。
3. 观察 `bsp_sys.c:157-163`：`WK_LP_INBOX_PENDING` 且 `poweron_vusb_out_en=True` 时自动开机。
**预期**：出仓可靠唤醒并按配置开机；唤醒率 20/20 次 ≥95%。

### T11 关机过程唤醒 pending 边界（PDF 红线）

**步骤**：
1. 触发关机（长按按键），在关机进行中立刻插入 5V（或模拟 inbox 变化）。
2. 观察是否发生系统立即 reset、关机失败。
3. 复现 10 次记录概率。
**预期**：确认为已知行为（PDF 5.4.3）；产品对策：配置 vusb 唤醒需等 5V 掉下去再关机、inbox 下降沿唤醒需 VUSB 维持电压。测试结论记录实际复位概率与影响。

### T12 充电相关灯效

**前置**：电源指示灯（红灯）使能（PDF 5.3.3）。
**步骤**：
1. 充电中：红灯亮（`led_charge_on()`，`bsp_charge.c:125`）。
2. 充满：按配置蓝灯亮/灯灭。
3. 低电（未充电）：红灯闪烁（低电灯效配置）。
4. 状态机回退（拔出）时灯及时熄灭（`led_charge_off()`）。
**预期**：各状态灯效与配置一致，切换无滞后错误。

### T13 电量检测

**步骤**：
1. 串口/调试口读取电池电量（SARADC 1s 周期采样，`bsp_saradc_vbat.c`）。
2. 与万用表实测 VBAT 对比，取 5 个电压点（3.0/3.4/3.7/4.0/4.2V）。
3. 观察滤波效果：快速晃动电压无跳变。
**预期**：误差 ≤±50mV（或按产品规格），显示无跳变。

### T14 充电线电压异常

**步骤**：
1. VUSB 供给异常电压（如 4.0V、5.5V、纹波大），观察 2s 周期检测（`bsp_charge.c:163-168`）。
**预期**：`[charge] CHARGE LINE VOLTAGE ERROR!!!` 打印出现，系统不损坏、不误判充满。

### T15 充电中拔出

**步骤**：
1. 恒流充电中直接撤掉 VUSB。
2. 观察状态回 `CHARGE_STA_OFF`、灯灭、功能恢复（边充边工作模式下音频/连接不中断）。
3. 快速插拔 50 次，观察无死机、无状态卡死。
**预期**：拔出后正常退出充电；插拔压力测试零异常。

### T16 插入 DC 复位系统（dcin_reset）

**前置**：`xcfg_cb.charge_dc_in_rst` 分别测 True/False。
**步骤**：工作状态下插入 5V，观察是否复位（True 时硬件 dcin 复位使能）。
**预期**：与配置一致；False 时插入不复位（走软件流程）。

### T17 仓内睡眠/关机唤醒源配置

**步骤**：
1. 在仓充电状态下进入休眠：确认 `sfunc_sleep_prepare`（`func_lowpwr.c:195-204`）选择 `WK_LP_INBOX`、禁 `WK_LP_VUSB`。
2. 不在仓时进入休眠：确认选择 `WK_LP_VUSB`、禁 `WK_LP_INBOX`。
3. 各状态下分别触发对应唤醒源验证能唤醒。
**预期**：唤醒源与 VUSB 状态联动正确，两种配置下均可被正确源唤醒。

### T18 维持电压类型仓（ch_box_type=2）

**前置**：`ch_box_type=2`，仓 VUSB 输出维持电压（<2.6V）。
**步骤**：
1. 工作状态入仓（VUSB 不升 5V）→ 确认 `func.c:59-66` 用 `CHARGE_INBOX()` 判定入仓并走关机。
2. 仓低电/高电两种供电情况下重复。
**预期**：维持电压仓下入仓关机判定正确，不依赖 5V 检测。

### T19 完整充放循环长稳

**步骤**：完整执行"放电→入仓充电→充满关机→出仓唤醒"循环 10 次，自动记录每次的三段时长与容量估算。
**预期**：10 次全部成功，充电时间一致性 ±10%，无累计异常。

## 5. 通过标准

1. P0 测试项 100% 通过；P1 项 ≥90% 通过且失败项不涉及安全；P2 项执行并有结论。
2. 无以下任一情况：死机、状态机卡死、充电中过流/过温、关机循环重启、唤醒丢失率 >5%。
3. 充电参数实测值与 `.setting` 配置偏差在允许范围（电流 ±10%、电压 ±20mV）。

## 6. 风险与说明

- 当前仓库 `BSP_CHARGE_BOX_EN=0`，充电仓专属代码（INBOX 判定、维持电压仓）未编译；执行 T2/T10/T17/T18 前需打开该宏重编译，并同步核对 `.setting` 的 `ch_box_type` 字段是否存在。
- 充电电流/温升/电池安全项必须硬件实测，日志与 map 文件不能作为通过依据。
- 若无真实充电仓，用可调电源模拟时注意：维持电压类型需要能输出 0~5V 连续可调且能突掉到 0V（模拟出仓），普通稳压源掉电沿不够陡时 INBOX 下降沿唤醒可能测不准，建议加 MOS 开关电路。
