# AB5766 LE Mic 算法测试执行记录

> 本文件保存每一次构建和硬件试验的事实记录。稳定的源码调用关系、算法边界和测试方法见 [../SDK/AB5766_LE_Mic_音频算法调用链与测试快速入门.md](../SDK/AB5766_LE_Mic_音频算法调用链与测试快速入门.md)。
>
> **记录规则：** 未完成构建身份、运行时配置身份或原始证据保存时，结论只能写 `Blocked` 或 `Inconclusive`；不得写“通过”。不要用宏名、日志名称或库符号单独推断算法行为。

## 1. 结论与证据等级

| 结论 | 含义 |
| --- | --- |
| `Pass` | 用例的全部通过准则满足，且 E0～E3 证据齐全 |
| `Fail` | 在已记录的条件下稳定复现不符合通过准则的现象 |
| `Blocked` | 前置门禁缺失，未进入有效试验 |
| `Inconclusive` | 已执行但证据不足以区分原因或得出结论 |

| 级别 | 本记录中需要保存的证据 |
| --- | --- |
| E0 | 相关产品配置、宏值、派生宏和发射/接收 setting 或 xcfg 快照 |
| E1 | 宏 → 初始化 → 帧处理 → 输出的真实源码调用关系与文件/函数/行号 |
| E2 | 本次构建的 map、固件产物、effect 与 xcfg 生成物身份 |
| E3 | UART、USB 音频、DAC/示波器、听音、照片或仪器原始记录 |

## 2. 每轮开始前门禁

在填写任何用例结果前，完成并保存以下清单：

- [ ] Git 提交 ID、分支、工作区状态、构建时间与工具链信息。
- [ ] 发射端与接收端各自的 setting / `xcfg.bin` 身份，及角色、MIC、RF、DAC 参数。
- [ ] `config.h` 产品选择、所有相关宏与 `config_extra.h` 派生关系。
- [ ] effect 资源、`xcfg.bin`、`app.rv32`、`app.bin`、`app.dcf`、`map.txt` 的时间戳和哈希或文件大小。
- [ ] 当次 `map.txt` 中相关实现/库符号和 RAM/Flash 余量；不可复用旧 map 证明新构建。
- [ ] 板号、硬件版本、供电、距离、天线方向、环境噪声、连接数量、声源和观测设备。
- [ ] 原始 UART、音频文件、仪器截图和照片已复制到可追溯位置。
- [ ] 已核验 `WIRELESS_MIC_RETRY_NB=3` 与源码同行“暂时支持 1/2”注释的不一致；在没有派生宏、当次构建和实际链路证据前，不对重传、丢包或 PLC 性能作结论。
