## 1. 概念理解题

### 题目 6.1 按键扫描周期与开机/关机时长的矛盾（★★★★ / 概念理解）

**题目**：`bsp_key_scan()` 默认 5ms 周期扫描，而 `PWRON_PRESS_TIME` 可以是 0.1s~3s。请解释：为什么用慢速扫描能检测出 0.1s 的短按？若按键在扫描间隔内按下并松开（即"窄脉冲"），会发生什么？

**考察点**：
- 主考点：按键扫描与消抖；
- 副考点：`key_status_process()` 的边沿检测；
- 区分点：能否区分“电平检测”与“事件检测”。

**参考答案**：
5ms 周期检测的是电平状态，不是脉冲。0.1s 长按会持续 20 个扫描周期，足以从 `KEY_NULL`→`KEY_DOWN`→`KEY_SHORT_UP`（若不到长按时间）或 `KEY_LONG`（若达到长按时间）。

**窄脉冲问题**：若按键在两次扫描之间（<5ms）按下并松开，电平未被采样到，事件丢失。当前设计认为物理按键不会这么快，且 `KEY_PRESS_MUTE_EN` 可选 1ms ISR 扫描缓解。

**评估标准**：
- ⭐⭐⭐ 能区分电平检测与窄脉冲丢失；
- ⭐⭐ 能说出慢扫描与短按的关系；
- ⭐ 完全不知道。

### 题目 6.2 消息队列的“积压”风险（★★★ / 概念理解）

**题目**：若 `func_process()` 中 `bt_run_loop()` 占用过多时间，导致 `msg_dequeue()` 延迟，按键消息会积压。当前如何避免“按了音量键后几秒才响应”？

**考察点**：
- 主考点：消息队列与主循环实时性；
- 副考点：`func_process()` 的任务拆分；
- 区分点：能否指出 `bt_run_loop()` 拆分或优先级。

**参考答案**：
当前设计：
1. `bt_run_loop()` 是非阻塞的，一次运行一轮；
2. `func_adapter_process()` / `func_mic_emit_process()` 中 `wireless_mic_proc()` 优先处理，按键消息在 `msg_dequeue()` 中立即处理；
3. 消息队列容量有限（`msg_queue_init()`），溢出会丢失最旧消息。

若需保证实时性，可考虑拆分 `bt_run_loop()` 为多份执行，或把按键扫描放入更高优先级任务。

**评估标准**：
- ⭐⭐⭐ 能指出当前方法的边界与改进；
- ⭐⭐ 能说出积压风险；

### 题目 6.4 `KEY_LONG_UP` 与低功耗唤醒的时序冲突（★★★★ / 源码追踪）

**题目**：在 `func_lowpwr.c` 中，系统会进入 sleep。若 K2 的“长按抬起”恰好发生在 sleep 唤醒后，按键事件如何被正确处理？请说出从 GPIO 唤醒中断到 `MSG_CHANGE_MAGIC` 的完整路径。

**考察点**：
- 主考点：唤醒后按键状态恢复；
- 副考点：`bsp_key_scan()` 与 `func_lowpwr.c` 的交互；
- 区分点：能否指出唤醒后第一次 `bsp_key_scan()` 会检测到 `KEY_LONG_UP` 并触发 MAGIC。

**参考答案**：
1. GPIO 唤醒中断触发 `lowpwr_need_exit_sleep()`；
2. 恢复时钟/外设后，`bsp_key_scan()` 重新启动；
3. K2 已经按下（长按中），`bsp_key_scan()` 检测到 `KEY_DOWN`；
4. 若在长按阈值前松手，`bsp_key_scan()` 检测到 `KEY_LONG_UP`；
5. `bsp_key_get_msg()` 查表得 `MSG_CHANGE_MAGIC`，入队；
6. 主循环 `func_mic_emit_message()` 处理 MSG，完成 MAGIC 切换。

**评估标准**：
- ⭐⭐⭐ 能说出 GPIO 唤醒→扫描→事件的完整路径；
- ⭐⭐ 能说出部分路径；
- ⭐ 完全不知道。

## 3. 调试排查题

### 题目 6.5 按键在 2.4G 干扰下的“误触发”问题（★★★★★ / 调试排查）

**题目**：实验室 2.4G 强干扰环境下，K1 音量+ 偶发“连击”（一次按键触发两次）。请给出 4 个可能原因，并从硬件滤波、软件消抖、消息队列、无线同步四个角度提出排查与改进建议。

**考察点**：
- 主考点：干扰环境下的按键可靠性；
- 副考点：硬件/软件协同消抖；
- 区分点：能否区分“硬件抖动”与“软件重复处理”。

**参考答案**：
1. **硬件滤波**：AD 按键的分压电阻/电容受 EMI 影响，电平抖动；改进：增大滤波电容、用示波器看波形；
2. **软件消抖**：当前消抖时间可能不足（如 20ms），干扰下多次扫描到边沿；改进：检查 `bsp_key_scan()` 消抖逻辑，把 20ms 改为 50ms；
3. **消息队列**：`KEY_DOWN` 事件重复入队，主循环每次 dequeued 都处理；改进：在 `func_mic_emit_message()` 中按时间戳去重；
4. **无线同步**：`wireless_tx_cmd_fw()` 失败后重试，导致 RX 收到多次音量命令；改进：增加命令序号或 ACK 机制。

## 4. 设计权衡题

### 题目 6.6 AD 按键 vs IO 按键的量产权衡（★★★★ / 设计权衡）

**题目**：当前工程 `BSP_ADKEY_EN=1, BSP_IOKEY_EN=0`，即用 SARADC 电阻分压按键，而非独立 IO 按键。请从 BOM 成本、按键数量限制、可靠性、调试难度四个角度评估，并说明为什么低功耗无线麦倾向用 AD 按键。

**考察点**：
- 主考点：硬件设计选型；
- 副考点：低功耗产品的约束；
- 区分点：能否指出 AD 按键的“节省 IO”与“上电即可检测”优势。

**参考答案**：
- **BOM**：AD 按键只需 1 个 ADC 通道 + 1 个电阻网络，比 3 个独立 IO 按键节省 2 个 GPIO 和外围电路；
- **按键数量**：AD 按键的分辨率有限，不能无限扩展；但本项目只需 3 键，足够；
- **可靠性**：IO 按键可配置内部上拉，抗干扰稍强；AD 按键需外部电阻网络，但可通过软件校准；
- **调试难度**：AD 按键需校准分压阈值，IO 按键即插即用；
- **低功耗**：AD 按键可用 SARADC 的低功耗扫描，IO 按键需保持 GPIO 供电。

**结论**：低功耗无线麦倾向 AD 按键以节省 GPIO 并支持低功耗扫描。

**评估标准**：
- ⭐⭐⭐ 能四角度评估并给出低功耗结论；
- ⭐⭐ 能三角度评估；
- ⭐ 只能说一个角度。
