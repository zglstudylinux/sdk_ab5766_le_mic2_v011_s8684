## 4. 难度分档

| 难度星级 | 对应级别 | 归入文件夹 | 题目类型倾向 |
|---|---|---|---|
| ★ / ★★ | 初级 | `junior/` | 概念理解、简单源码追踪 |
| ★★★ | 中级 | `mid/` | 源码追踪、调试排查、一般权衡 |
| ★★★★ / ★★★★★ | 高级 | `senior/` | 设计权衡、复杂调试、编程实战、架构题 |

**按岗位抽题建议**：

- 初级（应届/1-2年）：70% 初级题 + 30% 中级题，不出高级题；
- 中级（3-5年）：30% 初级 + 50% 中级 + 20% 高级；
- 高级（5+年）：15% 初级 + 35% 中级 + 50% 高级。

## 5. 评分标准

每题按 30 分制评估，难度系数加权：

| 难度 | 系数 |
|---|---|
| ★ | 1.0 |
| ★★ | 1.1 |
| ★★★ | 1.2 |
| ★★★★ | 1.35 |
| ★★★★★ | 1.5 |

三档标准：

- ⭐⭐⭐ **优秀**（27-30 分）：能引用具体文件:行号 + 推断设计意图 + 类比/横向对比；
- ⭐⭐ **合格**（18-26 分）：能描述机制 + 大致定位；
- ⭐ **不足**（0-17 分）：缺失关键引用 / 混淆功能 / 答非所问。

综合表现额外加 10 分（沟通、逻辑、诚实）。

## 7. 面试官版 vs 候选人版

- **面试官版**：完整四元组（题目/考察点/参考答案/评估标准）+ 陷阱提示；
- **候选人版**：仅保留 §0 背景与题目/考察点，去掉答案与评分，便于面试前发放。

## 8. 注意事项

- 候选人如提到看 `docs/SDK/算法详解/` 的资料，属于公开学习材料，不算作弊；
- 每道题必须含至少 1 个文件:行号引用，面试官可要求其展开；
- “当前默认宏值”以 `projects/microphone/config_ab5766_le_mic.h` 当前 HEAD 为准；
- 候选人如果只背诵历史 SDK 文档中已变更的配置（如 ECHO=1、USB Mic=1），按“引用过期资料”处理。

## 9. 更新与维护

- 每月或 SDK 大版本更新时核对一次“文件:行号”；
- 新增题目必须先补面试官版，再生成候选人版；
- 若改题，需同步更新 `junior/mid/senior` 三个对应镜像。
